# 基于MQTT协议的企业设备运行监测与远程控制系统 需求分析说明书

## 1. 项目背景与目标

随着工业企业设备数量的增加，传统的人工巡检、纸质记录方式已无法满足设备运行状态的实时监测与集中管控需求。本项目面向中小型企业的设备集中监测场景，构建一套基于 **B/S（Java Web）** 架构与 **MQTT** 协议的企业设备运行监测与远程控制系统，实现设备运行数据的自动采集、入库、可视化展示、异常告警与远程控制。

### 项目目标
1. 实现对多台设备的统一台账管理（设备信息、属性、控制参数）。
2. 通过 **MQTT** 协议自动采集设备上报的运行数据，解析 JSON 数据帧并持久化。
3. 通过 MQTT 向设备下发控制指令，实现远程控制。
4. 提供统计报表与图形化分析报表，辅助运维决策。
5. 实现基于角色的权限管理（RBAC），保证系统安全。

## 2. 角色与用户分析

| 角色 | 说明 | 主要权限 |
|------|------|----------|
| 超级管理员（admin） | 系统最高权限 | 全部功能：设备/属性/控制参数管理、控制下发、报表、用户/角色/权限管理 |
| 运维人员（operator） | 日常运维 | 设备与点位管理、数据查询与图形分析、控制下发、报表 |
| 访客（viewer） | 只读查看 | 数据查询、图形分析、报表查看（无增删改、无控制、无系统管理） |

## 3. 功能需求

### 3.1 设备管理
- 设备台账：新增、删除、修改、查询设备（编号、名称、类型、型号、厂商、位置、状态、安装日期等）。
- 设备属性（采集点 AI1~AI4 等）：对设备属性点位进行 CRUD，配置点位名称、单位、量程、缺省值等。
- 控制参数（控制点 DO1~DO4 等）：对控制点位进行 CRUD，配置点位名称、含义、缺省值等。

### 3.2 数据采集（MQTT）
- 系统订阅主题 `/kettle/pub`，接收采集器上报的运行数据。
- 解析 JSON 数据帧（`aiValueRpt`），将各采集点数值写入数据库。
- 数据帧示例：
```json
{
  "devId": "492C230518046576",
  "msgType": "aiValueRpt",
  "data": { "AI1": "0", "AI2": "4889", "AI3": "0", "AI4": "20" },
  "timestamp": "1688344552"
}
```

### 3.3 远程控制（MQTT）
- 用户在界面选择设备与控制点，设置目标值，系统封装 JSON 控制帧。
- 向主题 `/{devId}/sub` 下发控制帧（`doValueRpt`）。
- 控制帧示例：
```json
{
  "devId": "492C230518046576",
  "msgType": "doValueRpt",
  "data": { "DO1": "0", "DO2": "0", "DO3": "0", "DO4": "0" },
  "timestamp": "1687333310"
}
```
- 记录控制下发日志（操作人、目标值、时间、状态），供审计追溯。

### 3.4 数据查询与图形分析
- 按设备、点位、时间范围查询历史采集数据。
- 最新数据实时看板（每个点位的最新值）。
- 折线图展示点位运行趋势（ECharts）。

### 3.5 统计报表
- 设备总量、在线/离线数、点位总数、今日采集条数、控制次数等汇总。
- 按设备类型分布的统计图表。
- 点位数值统计（最大值/最小值/平均值）。

### 3.6 权限管理
- 用户管理：用户 CRUD、启用/停用、重置密码、分配角色。
- 角色管理：角色 CRUD、为角色分配菜单/按钮权限。
- 菜单/权限管理：菜单树维护。
- 登录认证：基于 JWT，前端根据权限动态渲染菜单与按钮。

## 4. 非功能需求
1. **安全性**：密码 BCrypt 加密存储；接口基于 JWT 鉴权；按钮级权限控制。
2. **易用性**：界面规范、符合用户操作习惯（列表 + 搜索 + 分页 + 弹窗表单 + 操作确认）。
3. **可靠性**：MQTT 断线自动重连；MQTT 连接状态可视化。
4. **可维护性**：分层架构（Controller / Service / Repository），统一返回结构与异常处理。
5. **性能**：采集数据按设备与时间建立索引，支持分页与时间范围查询。

## 5. 运行环境
- JDK 21
- Maven 3.9+
- MySQL 8/9
- Node.js 18+（前端构建）
- MQTT Broker（默认使用内嵌 Moquette，端口 1883，可切换外部 Broker）

## 6. 验收标准对照

| 编号 | 验收标准 | 实现方式 |
|------|----------|----------|
| 1 | 界面标准，符合用户习惯 | Element Plus 组件化界面，统一布局/搜索/分页/表单 |
| 2 | 真实的权限管理 | Spring Security + JWT + RBAC，动态菜单与按钮级控制 |
| 3 | 设备/属性/控制参数 CRUD | 设备管理、点位管理模块 |
| 4 | MQTT 采集并解析入库 | 订阅 `/kettle/pub`，解析 `aiValueRpt` 写入 `device_data` |
| 5 | MQTT 控制发送并封装 JSON | 封装 `doValueRpt` 下发到 `/{devId}/sub` |
| 6 | 基本信息统计报表 | 统计看板 + 设备类型分布 + 点位数值统计 |
| 7 | 图形分析报表 | ECharts 趋势折线图、分布饼图 |
| 8 | 程序运行正常无错误 | 完整构建 + 冒烟测试通过 |
